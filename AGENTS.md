# AGENTS.md

Общие инструкции для AI-агентов, работающих с репозиторием RepoDocs.

Этот файл — основной источник общих правил проекта. Инструменты, поддерживающие формат `AGENTS.md` (в частности OpenAI Codex), могут загружать его автоматически. Если среда агента не загружает этот файл автоматически, агент должен прочитать его перед началом работы, когда это возможно.

## О проекте

**RepoDocs** (репозиторий `repo-docs-tracker`) — local-first, AI-native система управления проектным контекстом: документация, знания, требования, технические решения и задачи хранятся в Git-репозитории проекта и доступны человеку и AI-агентам.

**Текущая стадия:** продуктовое и архитектурное проектирование. Основные артефакты — документация; наличие или отсутствие реализации проверяй по текущему состоянию репозитория.

## Источники истины

- [docs/product/product-vision.md](docs/product/product-vision.md) — продуктовое видение и границы продукта. Это главный ориентир при оценке новых предложений.
- [docs/architecture/architecture-overview.md](docs/architecture/architecture-overview.md) — согласованный архитектурный обзор, если файл присутствует в текущей ветке.
- Остальные спецификации и ADR в `docs/` уточняют соответствующие области.

Не выдавай гипотезы и предложения за принятые решения. Если предложение противоречит зафиксированным решениям или принципу лёгковесности, явно укажи, что потребуется пересмотр решения. Не меняй смысловые договорённости без согласования пользователя.

## Структура репозитория

- `docs/product/` — продуктовые документы.
- `docs/architecture/` — архитектура, модель данных и технические спецификации.
- `docs/reviews/` — результаты ревью документов (`<документ>-v<версия>-review.md`).
- Другие тематические разделы добавляй по мере появления устойчивой потребности.

## Рабочий процесс

- Все изменения делай в отдельных ветках с конвенциональным префиксом: `docs/`, `feat/`, `fix/`, `chore/` и т. п.
- Не коммить напрямую в `main`. Слияние выполняется через Pull Request; окончательное слияние делает пользователь.
- Перед изменениями изучи актуальное состояние ветки и связанные документы. Не полагайся только на прежний контекст разговора.
- Для ревью используй обсуждение PR и inline-комментарии. В репозитории сохраняй инженерные выводы, принятые/отклонённые предложения с обоснованием, новые решения и открытые вопросы, но не стенограмму обсуждения.
- Не считай замечания другого AI-агента автоматически принятыми решениями.
- Не переписывай историю существующих коммитов ради косметического изменения атрибуции без явного согласования пользователя.

## Документация

- Вся человекочитаемая документация — на русском языке.
- Используй Markdown с GitHub Flavored Markdown (GFM).
- Сохраняй существующую структуру и терминологию документов.
- При переносе или форматировании документа без запроса на смысловую редактуру не меняй его содержание.
- Новые архитектурные и продуктовые решения явно отделяй от предложений, гипотез и открытых вопросов.

## Git и сообщения коммитов

### Формат

- Используй Conventional Commits: `docs:`, `feat:`, `fix:`, `chore:` и другие подходящие префиксы.
- Заголовок коммита пиши на русском языке.
- Если изменения содержательные, body обязателен: короткий заголовок/контекст и развёрнутый список того, что изменено и зачем.
- Body можно опустить только для тривиальных изменений, когда он действительно не добавляет смысла (например, простое переименование файла или правка `.gitignore`).
- В конце сообщения добавляй трейлеры соавторства для AI-агентов, реально участвовавших в подготовке изменений. Между body и трейлерами оставляй пустую строку.

### Атрибуция AI-агентов

Используй идентификатор, соответствующий фактически использованному агенту или интеграции. Не подменяй одного агента другим и не придумывай адреса. Трейлер `Co-Authored-By` — это метаданные атрибуции; сам по себе он не меняет Git author/committer и не является криптографическим доказательством участия.

| Агент / интеграция | Трейлер |
| --- | --- |
| ChatGPT через GitHub connector (текущая интеграция) | `Co-Authored-By: ChatGPT <199175422+chatgpt-codex-connector[bot]@users.noreply.github.com>` |
| OpenAI Codex CLI | `Co-Authored-By: Codex <noreply@openai.com>` |
| Claude Code | `Co-Authored-By: Claude Code <noreply@anthropic.com>` |

Адрес Codex CLI подтверждается репозиторием OpenAI Codex; адрес ChatGPT connector соответствует GitHub Bot-аккаунту интеграции. Запись Claude Code сохраняет принятую в проекте договорённость.

Для других агентов:
1. Найди адрес в официальной документации поставщика или в коммитах/репозиториях, однозначно связанных с официальным GitHub-аккаунтом агента.
2. Проверь, что адрес действительно привязан к соответствующему GitHub-профилю, если это возможно.
3. Только после проверки добавляй новую строку в таблицу.
4. Если надёжно подтвердить адрес не удалось, не выдумывай его: сообщи пользователю и оставь коммит без неподтверждённого трейлера либо запроси решение.

Добавляй трейлер только для агента, который действительно участвовал в подготовке данного коммита. Если участвовало несколько агентов, укажи каждого отдельным трейлером. Не дублируй один и тот же трейлер.

## Приём и подготовка документов

Когда агент готовит документ для включения в репозиторий:

1. Работай в ветке `docs/<тема>`.
2. Проверь разметку и доведи её до GFM без смысловых правок, если пользователь не просил редактуру.
3. Перечисли пользователю смысловые изменения относительно предыдущей версии, если они были.
4. Замечания по существу выноси в review-документ или PR-комментарии; блокирующие противоречия с Product Vision и другими согласованными документами сообщай сразу.
5. Предлагай Pull Request для включения изменений в `main`.

## Общий принцип

RepoDocs — долгосрочный проект. Сохраняй непрерывность решений и контекста, предпочитай простые расширяемые решения и не добавляй подсистемы без подтверждённого сценария.
